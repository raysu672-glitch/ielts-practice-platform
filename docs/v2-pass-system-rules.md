## 0. 一句话

**新版是一场以「过关」为胜负、以即时反馈为燃料、以自愿进入为前提的严肃学习游戏；师生共用同一套语言。旧系统继续托住现有排单与双并轨运营，试验期内默认不改旧系统代码与主流程。**

---

## 1. 为什么做新版（问题定义）

### 1.1 已确认的事实前提

1. 主因不是任务过重，而是**当天排单经常执行不稳**（习惯断档、零完成日多、少测少反馈）。
2. **未完成项继续留在计划中、照常排单**；不得用「积压山压垮」解释行为。
3. 平台与企微群双并轨中：催有一定效果，但**纯催无法变成主动学**；完善平台后目标是取消群打卡。
4. 群报与平台练经常错位（有练无报 / 有报无练）；**完成真相不能以群打卡为准**。

### 1.2 本说明书要解决的问题

> 如何在**不动旧系统**的前提下，用一套极简新版验证：  
> **「短练 → 测/过关 → 看见变化」能否让学生更主动打开、更稳定有效学习。**

### 1.3 明确不解决（本试验边界外）

- 不重做全站模块与自动排课引擎  
- 不在新版内重建企微打卡考勤  
- 不把新版做成「更聪明的催人工具」  
- 不在未经验证前全员强制、不立刻砍掉旧流程

## 2. 宪法级原则（不可违背）

### P1 · 单位是「关」，不是「打卡」

学习与教学对话的基本单位是**关（Quest / Gate）**。  
禁止把「回了好的 / 群里报了 / 打开过页面」定义为完成。

### P2 · 核心环必须闭合

每一次有效尝试应尽量走到：

```text
短练 → 立刻测或判定 → 给出过/未过与差距 → 未过可针对再试 → 进步被看见
```

缺测、只有打勾、只有催，视为环未闭合，不算新版成功样本。

### P3 · 四件套必须同时成立（游戏改变世界）

| 件套 | 本系统含义 | 违规例子 |
|------|------------|----------|
| **目标** | 学生知道今天怎样算赢 | 只有模糊「去学习」 |
| **规则** | 过关条件事先公开、可执行 | 事后改标准、或混时长即可过 |
| **反馈** | 努力后尽快知道离目标多近 | 练完无结果、隔天被催才知 |
| **自愿** | 进入新版是选择；可回旧版 | 惩罚式强制、断签羞辱 |

### P4 · 追求 Fiero，不追求外挂 integr

优先设计「有点难、过了有自豪感」的关，而不是空积分、徽章墙、排行榜垫底羞辱、断签惩罚。

### P5 · 教师是关卡教练，不是监工

教师动作围绕：**已过关 / 来了但未过（卡点） / 未打开**。  
禁止把新版教师端做成群催打卡的网页版。

### P6 · 旧系统托底，新版证伪/证实

试验期旧系统默认不动。新版失败可以关掉；不得为了试验破坏现网排单与数据真相（除非另文明确「试验班切换规则」）。

### P7 · 成功看主动与过关，不看被催次数

验收指标见第 9 节。群里回复率、催的次数**不得**作为新版成功主指标。

## 3. 术语表（强制统一）

| 术语 | 定义 |
|------|------|
| **关** | 一条有公开过关条件的学习挑战；有胜负。 |
| **今日主关** | 当日默认要打的那一关（通常 1 个）。 |
| **过关** | 满足该关事先公布的判定条件，系统记为 `passed`。 |
| **未过关** | 有过关尝试但未达条件，记为 `attempted_failed`；必须给出差距。 |
| **未打开** | 当日无新版有效进入/无开打记录，记为 `not_started`。 |
| **有效学习日** | 当日至少完成一次「有反馈的尝试」（过关或未过但有判定结果）。纯打开无练不计入。 |
| **可见进步** | 学生对自己展示的、可理解的变化信号（如正确率相对基线、连续有效日、本周过关数）。 |
| **Fiero 时刻** | 过关成功被明确告知的那一刻（学生必须感知到「赢了」）。 |
| **旧系统** | 现行排单 / 打勾 / 教师端 / 双并轨流程。 |
| **新版** | 本说明书约束下的极简过关试验系统（师生两端）。 |
| **试验班** | 被允许进入新版、纳入试验统计的学生集合。 |

## 4. 关的规则（游戏规则本体）

### 4.1 一条关必须具备的字段（逻辑字段，非表结构）

1. **目标陈述**（一句话：今天要赢什么）  
2. **过关条件**（可判定、事先可见，例如正确率 / 遍数 / 限时内完成等）  
3. **允许的行动**（练什么、测什么；不可用的捷径需写明）  
4. **反馈内容**（过/未过、分数或对错摘要、与自身基线的对比若有）  
5. **未过时的下一步**（针对错因的再练建议；禁止只显示「去完成任务」）  
6. **难度意图**（应落在「跳一跳够得着」；过易无 Fiero，过难无紧急乐观）

### 4.2 胜负与尝试

- **一次尝试** = 进入开打 → 产生判定结果。  
- 同一日允许对主关**多次尝试**（未过可再打），以最后一次或首次过关规则在具体规格中二选一写死；**默认：当日首次 `passed` 即算今日主关已过，额外再打记为加练。**  
- **禁止**：只计时长达标、无判定也算过关。  
- **禁止**：把「打开模块页」算过关。

### 4.3 每日结构（逻辑）

- 默认：**1 个今日主关**。  
- 可选：**至多 1 个加练关**（主关已过之后才出现，或学生自愿点开）。  
- 禁止把新版做成与旧系统等长的任务清单拷贝。

### 4.4 反馈时效

- 判定结果须在当次尝试结束时给出（即时或近即时）。  
- 「看见进步」须在学生回访首页时仍可见（至少覆盖本周）。

### 4.5 内容选型原则（本说明书不锁死题型）

选型服从：

1. 能快速出判定；  
2. 学生能理解「我好了一点」；  
3. 与机构提分路径相关（史诗意义可接到出分目标）。  

具体首发题型（词测 / 跟读 / 错题回测等）在《具体规格》中单独立项，**不得与本规则冲突**。

## 5. 学生侧规则

### 5.1 进入与自愿

1. 学生从旧站入口选择「新版」进入；须能返回旧版。  
2. 非试验班可隐藏入口或进入后提示「未开放」。  
3. **禁止**以断签、扣分、公开羞辱迫使留在新版。

### 5.2 学生打开新版时应能回答的三个问题

1. 我最近有没有变好？（可见进步）  
2. 今天要赢哪一关？（今日主关目标）  
3. 过了/没过之后我干什么？（下一步）

无法回答则视为产品违规，不视为学生态度问题。

### 5.3 学生行为状态机（按日）

```text
not_started
  →（开打并出判定）→ attempted_failed 或 passed
attempted_failed
  →（再打）→ attempted_failed 或 passed
passed
  →（可选加练）→ 仍保持当日主关 passed
```

### 5.4 自主感（最小必需）

至少满足其一（具体规格任选落地）：

- 主关内步骤顺序可选；或  
- 过关后加练方向可选；或  
- 当日「先看进步 / 先开打」可选。  

禁止全程纯强制无任何选择点。

### 5.5 学生侧明确不做

- 群打卡入口与群完成定义  
- 完整模块大厅搬迁  
- 复杂计划树编辑  
- 以催更红点为首页主元素  
- 排行榜垫底曝光作为主激励

## 6. 教师侧规则

### 6.1 教师新版的唯一主视图逻辑

教师按试验班学生，按日（或近几日）看见且仅需优先处理三类：

| 状态 | 含义 | 允许的教师动作 | 禁止的动作 |
|------|------|----------------|------------|
| **已过关** | 当日主关 `passed` | 简短肯定进步；少打扰 | 再催打卡 |
| **卡点** | 有尝试未过，或反复失败 | 问错因、降难、陪过一关、调整关的难度意图 | 骂态度、唯催「去做完」 |
| **未打开** | `not_started` | 有限次触达或召回，话术围绕「回来打今日一关」 | 刷屏催、无限加频 |

### 6.2 话术规则（教学口径）

- 标准问法：**「这关过了吗？卡在哪？」**  
- 禁止主问法：**「怎么还不打卡？」**  
- 肯定进步时指向**具体过关/进步信号**，禁止空泛「要加油」。

### 6.3 催的降级与封顶

1. 新版内「未打开」触达有频次上限（具体数字在运营细则写死；原则是**有限次**）。  
2. 连续多日未打开 → 升级为人工召回/面谈，**不是**提高催频。  
3. 催不得替代过关闭环；无反馈的催记为旧范式，不计入新版方法论成功。

### 6.4 教师详情最低信息

点开学生须能看到：

- 过关时间线（近日）  
- 最近未过的差距/错因摘要（有则显示）  
- 可见进步摘要  

禁止把详情做成旧任务勾选表的镜像作为主界面。

### 6.5 教师侧明确不做

- 企微群消息群发器  
- 打卡统计看板作为主 KPI  
- 与旧教师端功能对等搬家  
- 用排行榜公开羞辱未完成者

## 7. 新旧系统边界规则

### 7.1 代码与产品边界

1. 旧系统主流程、排单、打勾、现网教师端：**试验期默认零改动**（若需入口链接，单独作为极小变更立项）。  
2. 新版独立入口、独立页面/路径、独立规则实现。  
3. 提交与部署须遵守仓库「子任务范围」：只含本子任务文件。

### 7.2 完成真相（试验期必须先选定一种，写进试验班通知）

下列两选一，**禁止混用双真相**：

| 方案 | 含义 | 动力强度 | 风险 |
|------|------|----------|------|
| **A. 试验班以新版过关为准** | 当日主关 `passed` = 当天学习要求满足；旧排单对该班暂停或降权 | 高 | 需运营配合 |
| **B. 新版纯体验** | 正式仍认旧版打勾；新版只作体验与观测 | 低 | 学生可能不当真 |

**未选定前，不得宣称「已经用新版替代旧完成定义」。**  
（选定结果应回写本节；当前状态：**待负责人拍板**。）

### 7.3 群打卡

- 新版**自身不提供**群打卡完成定义。  
- 旧群打卡是否保留，由机构运营决定；**新版成功并具备教师过关态势后**，再启动取消群打卡，不在本规则内提前砍群。

### 7.4 数据与对照

试验须能对照至少：

- 打开/开打天数  
- 有效学习日  
- 主关过关率、尝试次数  
- 零完成/未打开天数  

企微数据仅作本机可选分析，**不是**新版完成依据。

## 8. 试验运营规则

### 8.1 人群

- 优先：仍在学但不稳（有打开或间断完成、非长期休眠）的小样本。  
- 休眠生不作为验证「主动学」的首批主样本（可另做召回试验）。  
- 建议量级：先十余人至二十人量级，再扩面。

### 8.2 周期

- 须有基线期（旧行为）与试验期；周期长度在具体方案写死。  
- 中途改过关条件须版本化，避免「规则漂移」污染结论。

### 8.3 教师负担

- 试验期教师主要使用新版过关态势；避免要求教师旧新两套全功能双开同等深度。  
- 若必须双开，须在运营上减负（班级人数、其他催更任务下降）。

### 8.4 退出

- 学生可回旧版；退出原因宜可记录（可选）。  
- 试验可整体叫停；叫停不得损坏旧系统数据。

## 9. 成功 / 失败判定（逻辑验收）

### 9.1 主成功信号（需同时看趋势，不唯单一指标）

相对基线，试验班出现：

1. **主动打开 / 开打天数上升**  
2. **有效学习日上升**，整日未打开或无反馈尝试下降  
3. **主关过关参与上升**（环在转）  
4. 学生能感知进步（问卷或访谈可选，至少抽查）

### 9.2 假成功（判无效）

- 仅催频上升、打开未升  
- 仅群回复变多、平台无判定  
- 过关条件过松导致「人人天天过」但无难度与 Fiero  
- 靠惩罚连胜维持登录

### 9.3 失败后的动作

承认证伪 → 调整关设计或难度或反馈，或停止扩面；**禁止**用加大催更掩盖失败。

## 10. 禁止清单（总表）

1. 用新版复刻群催打卡  
2. 无判定的时长/打开算过关  
3. 双真相（群、旧勾、新关同时都算正式完成且不声明优先级）  
4. 空积分 / 羞辱榜作为主驱动  
5. 为试验大改旧系统核心  
6. 把「积压压垮」写进对学生的归因话术  
7. 未打开就无限加催  
8. 师生语言不一致（学生说过关、老师仍只盯打卡）
